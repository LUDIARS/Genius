# 起動中プロセスの dist 陳腐化を検知するビルド鮮度チェックの実装

## 目的

前 run (`32389f09-6eb5-4050-85f6-0d28f3f3afdd`) から引き継いだ課題:
run `01M17EW8CHDEZA7C2FEYAZ21NP` が `status=running`/`filesProcessed=0` の
まま無進捗に見え、恒久対策として「claude-cli 呼び出しのタイムアウト/
ヘルスチェック/自動リトライ機構」の実装が必要と note に記載されていた。

## 調査結果 (2026-08-29, このセッション)

- 実際には run は停滞していなかった。`logs/ingest.jsonl` は約 30〜90 秒
  ペースで `document-completed`/`document-skipped` を記録し続けており、
  `cardsCreated` も着実に増えていた (review ソースの category 発明による
  `document-failed` は既知現象 [[project_tier2-distillation-failing]] の
  範囲内で、run 全体を止めていない)。
- しかし `GET /api/clone/ingest/runs/:id` は `filesProcessed: 0` を返し
  続けていた。`data/genius.db` を直接 SELECT したところ
  `distill_runs.files_processed` が実際に 0 のまま更新されていないことを
  確認 (`notes` は `{"status":"running",...}` のまま)。
- これは `spec/feature/operations.md` §11 (`SPEC-GENIUS-INGEST-RUN-PROGRESS`,
  commit 3313e33/4152037, 2026-08-26 main マージ済み) の fix が
  **未反映のプロセスがまだ稼働していた**ことが原因。`dist/ingest/*.js` の
  mtime が 2026-08-25 15:31 (fix マージ前のビルド) のままで、
  `grep SPEC-GENIUS-INGEST-RUN-PROGRESS dist/ingest/ingest-service.js` が
  0 件だった (ソース側には存在)。
- つまり claude-cli 呼び出し自体のハング/タイムアウト不足が原因ではなく、
  「main にマージされた fix が Excubitor 常駐プロセスの再ビルド無しには
  反映されない」という運用ギャップの再発だった。`restart_policy: on-failure`
  はクラッシュ時のみ再起動するため、ソース更新だけではプロセスは
  入れ替わらない。
- 元の delegation note にあった「claude-cli タイムアウト/ヘルスチェック/
  自動リトライ」は再検証の結果、**既に実装済み**だった
  (`src/distill/claude-cli-llm.ts`: `COMPLETION_TIMEOUT_MS`=5分の
  タイムアウト、`assertReady()`によるモデル疎通ヘルスチェック、
  `json-completion.ts`の`requestValidatedJson`によるJSON検証失敗時の
  2回リトライ)。追加実装が必要なのはこの経路ではなく、
  「fix が実プロセスに反映されているか」を可視化する仕組みだった。

## 実装したこと

- `src/runtime/build-freshness.ts` を新設。`checkBuildFreshness(srcDir, distDir)`
  が `src/**/*.ts` (`.d.ts` を除く) と対応する `dist/**/*.js` の有無と mtime を
  比較し、出力が無いか src が新しいファイルが 1 件でもあれば
  `{ stale: true, staleSample }` を返す。`dist/` が丸ごと無い (未ビルド) 場合は
  stale 扱いにしない。
- `src/server.ts` の起動シーケンス冒頭で `checkBuildFreshness()` を呼び、
  stale なら `[build] dist/ appears stale ...` を stderr へ出す。起動は
  止めない (fail-fast の対象は「設定不備」であり、ビルド鮮度は運用上の
  警告のため)。
- 評価結果を `createRuntime({ buildStale })` 経由で `HealthService` に渡し、
  `GET /readyz` の応答へ `buildStale: boolean` を追加。`/healthz` は
  §9 (`SPEC-GENIUS-HEALTH-READINESS`, I/O 無し契約) を維持するため対象外。
- `spec/feature/operations.md` に `## 12. dist 鮮度チェック (2026-08-29)`
  (`SPEC-GENIUS-BUILD-FRESHNESS`) を追記。
- `test/runtime/build-freshness.test.ts` を新設 (fresh/stale/未ビルド/
  個別出力欠落/`.d.ts`除外の5ケース + 警告メッセージのフォーマットテスト)。
- 既存テスト (`test/api/clone-api.test.ts`, `test/api/security-limits.test.ts`,
  `test/api/ui-static.test.ts`) の `ReadinessStatus` 期待値・`HealthService`
  コンストラクタ呼び出しを新シグネチャに追従。
